# 宣言

Oh My OpenCode 背后的原则和理念。

---

## 人类干预是失败信号

**人在环路 = 瓶颈**
**人在环路 = 瓶颈**
**人在环路 = 瓶颈**

想想自动驾驶。当人类必须接管方向盘时，那不是一个功能 - 那是系统的失败。汽车无法自己处理情况。

**编码为什么有所不同？**

当您发现自己：
- 修复 AI 的半成品代码
- 手动纠正明显的错误
- 一步步引导代理完成任务
- 反复澄清相同的需求

...那不是"人机协作"。那是 AI 未能完成其工作。

**Oh My OpenCode 建立在这个前提上**：在代理工作期间的人类干预根本上是一个错误信号。如果系统设计正确，代理应该在不需要您监督的情况下完成工作。

---

## 不可区分的代码

**目标：代理编写的代码应与高级工程师编写的代码不可区分。**

不是"需要清理的 AI 生成代码"。不是"一个好的起点"。而是实际的、最终的、生产就绪的代码。

这意味着：
- 完全遵循现有代码库模式
- 在不被要求的情况下适当的错误处理
- 测试真正测试正确的东西
- 没有 AI 陈词滥调（过度工程、不必要的抽象、范围蔓延）
- 仅在添加价值时才有注释

如果您能分辨出提交是由人类还是代理做出的，那么代理就失败了。

---

## Token 成本 vs. 生产力

**如果显著提高生产力，则较高的 token 使用是可以接受的。**

使用更多 token 来：
- 让多个专业代理并行研究
- 在没有人工干预的情况下完全完成工作
- 在完成前彻底验证工作
- 跨任务积累知识

...当它意味着 10 倍、20 倍或 100 倍生产力提升时，这是一项值得的投资。

**然而：**

不追求不必要的 token 浪费。系统优化：
- 对简单任务使用更便宜的模型（Haiku、Flash）
- 避免冗余探索
- 跨会话缓存学习
- 在收集到足够上下文时停止研究

Token 效率很重要。但不以牺牲工作质量或人类认知负荷为代价。

---

## 最小化人类认知负荷

**人类应该只需要说出他们想要什么。其他一切都是代理的工作。**

实现这一目标的两种方法：

### 方法 1：Prometheus（访谈模式）

您说："我想添加身份验证。"

Prometheus：
- 研究您的代码库以理解现有模式
- 根据实际发现提出澄清性问题
- 浮现您未考虑的边缘情况
- 在您做出决策时记录决策
- 生成完整的工作计划

**您提供意图。代理提供结构。**

### 方法 2：Ultrawork（只管做模式）

您说："ulw 添加身份验证"

代理：
- 找出正确的方法
- 研究最佳实践
- 遵循约定实现
- 验证一切正常
- 继续直到完成

**您提供意图。代理处理一切。**

在这两种情况下，人类的工作是**表达他们想要什么**，而不是管理如何完成。

## 可预测、连续、可委托

**理想的代理应该像编译器一样工作**：markdown 文档进入，工作代码出来。

### 可预测

给定相同的输入：
- 相同的代码库模式
- 相同的需求
- 相同的约束

...输出应该是一致的。不是随机的，不是令人惊讶的，不是以您没有要求的方式"有创意"。

### 连续

工作应该经得起中断：
- 会话崩溃？用 `/start-work` 恢复
- 需要离开？进度被跟踪
- 多日项目？上下文被保留

代理维护状态。您不必。

### 可委托

就像您可以将任务分配给有能力的团队成员并信任他们处理一样，您应该能够委托给代理。

这意味着：
- 明确的验收标准，独立验证
- 出错时的自我纠正行为
- 升级（到 Oracle，到用户）仅在真正需要时
- 完整的工作，而不是"大部分完成"

---

## 核心循环

```
人类意图 → 代理执行 → 已验证结果
       ↑                              ↓
       └──────── 最小 ─────────────┘
          （仅在真正失败时干预）
```

Oh My OpenCode 中的一切都旨在使这个循环工作：

| 功能 | 目的 |
|---------|---------|
| Prometheus | 通过智能访谈提取意图 |
| Metis | 在歧义成为错误之前捕获它们 |
| Momus | 在执行前验证计划是否完整 |
| 编排器 | 在没有人工微观管理的情况下协调工作 |
| 待办事项继续 | 强制完成，防止"我完成了"谎言 |
| 类别系统 | 在没有人工决策的情况下路由到最佳模型 |
| 后台代理 | 不阻塞用户的并行研究 |
| 智慧积累 | 从工作中学习，不重复错误 |

---

## 这在实践中意味着什么

**您应该能够：**

1. 描述您想要什么（高级或详细，您选择）
2. 让代理在需要时访谈您
3. 确认计划（或只是让 ultrawork 处理）
4. 走开
5. 回来看到完成、验证、生产就绪的工作

**如果您不能做到这一点，系统中有些东西需要改进。**

---

## 我们正在构建的未来

一个世界：
- 人类开发者专注于**构建什么**，而不是**如何让 AI 构建它**
- 代码质量独立于谁（或什么）编写了它
- 复杂的项目和简单的项目一样容易（只是需要更长时间）
- "提示工程"变得像"编译器调试"一样过时

**代理应该是不可见的。** 不是在隐藏的意义上，而是在它只是工作的意义上 - 就像电、自来水、互联网一样。

您拨动开关。灯亮了。您不会想到电网。

这就是目标。
